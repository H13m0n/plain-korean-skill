# 패턴과 예외

아래 예시는 모두 새로 쓴 가상 문장이다. 단어보다 문장의 기능을 보고 적용한다. 전체 예시와 유지 사례는 [examples.jsonl](examples.jsonl)에 있다.

| 살필 전개 | 편집 기준 |
|---|---|
| 제안 설명 뒤마다 미정 상태 반복 | 제목·머리말에서 범위를 설명하고 중복을 삭제한다. 일정과 결정을 묻는 글에는 상태를 남긴다. |
| 요청하지 않은 비교로 역할 설명 | 해당 대상의 주체·동작을 쓴다. 비교 질문에는 차이를 답한다. |
| 검색·확인 과정이 본문을 차지 | 독자에게 필요한 결과와 근거를 쓴다. 조사 실패가 판단에 중요하면 남긴다. |
| 추상적인 관리 동사 | 기록할 값, 검사할 위치, 가져와 쓸 절차를 쓴다. 정확한 기술 행위를 뜻하면 유지한다. |
| 주장 뒤에 관성적인 평가 필요 문장 | 주장의 주체를 밝힌다. 실제 평가 계획과 불확실성은 필요한 위치에 남긴다. |
| 개요에서 날짜·버전·식별자 나열 | 호환성·재현·일정에 필요한 값만 본문에 둔다. 출처 기록의 정밀 정보는 보존한다. |
| “뿐 아니라 함께”로 항목 추가 | 비교할 항목을 직접 나열한다. 실제 추가 관계를 강조할 필요가 있으면 유지한다. |
| 명사끼리 이어 붙인 표현 | 누가 무엇을 설명하는지 연결한다. 고유 명칭은 유지한다. |
| 가정한 테스트를 관찰 사례로 소개 | 가정과 관찰을 구별한다. 대표성이 확인된 사례는 그 범위대로 쓴다. |
| 같은 대상의 이름을 계속 변경 | 이름을 통일한다. 서로 다른 대상의 차이는 유지한다. |
| 설명 뒤에 붙인 반복 결론 | 새 정보가 없으면 삭제한다. 독립해서 읽는 요약은 남길 수 있다. |
| 짧게 끊긴 동작 설명 | 원인·조건·결과를 연결한다. 독자가 따라 할 단계는 나눌 수 있다. |

예를 들어 “캐시는 조회를 줄인다. 이 저장 계층은 결과를 보관한다. 해당 보관 장치는 다음 요청에 응답한다.”는 같은 대상을 다른 이름으로 부른다. “캐시는 결과를 보관해 다음 조회에 사용한다.”로 연결할 수 있다.

반면 “연결이 끊겨도 작업은 계속 실행된다”는 장애 조건을 설명한다. 부정·조건 표현이 있다는 이유로 삭제하지 않는다. “삭제한 자료는 복구할 수 없다”도 실제 제한이면 그대로 남긴다.

새 기준은 수정 예와 함께 **유지할 문맥**을 포함해야 한다. 글의 목적이 다른데 한 가지 문체를 강요하지 않는지 확인한다.
