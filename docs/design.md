# 공개본 구조와 설계 판단

## 기존 구성에서 가져온 것

기존 스킬은 문장·문단 편집 지침, 피드백 패턴, 공개 글 검토 기록, JSONL 사례집과 검색 도구, 에이전트 표시 정보로 구성돼 있었다. 문장 필요성과 실제 동작을 먼저 읽고 의미를 대조하는 기준을 유지했다.

개인 피드백 기록에는 작성 시점, 개인 문서의 주제, 프로젝트·제품·환경 이름, 별도 관리 저장소 경로가 섞여 있었다. 사례집에는 원본 데이터 외에도 카드·색인·검색 화면용 데이터가 있어 원본 파일만 손봐서는 같은 내용이 다른 파일에 남을 수 있었다.

## 공개 범위

| 구성 | 공개본 처리 |
|---|---|
| 문장 필요성·전개·의미 보존 | 특정 사용자 표현을 제거하고 독자와 용도를 기준으로 정리 |
| 실제 피드백과 프로젝트 문장 | 원문·문맥을 옮기지 않고 새 가상 예시로 작성 |
| 외부 글의 수집·평가 자료 | 초기 배포에서 제외. 실제 자료를 추가할 때는 출처·재배포 권리 검토 |
| 생성 카드·색인·검색 화면 | 이전 생성물을 복사하지 않고 작은 JSONL을 직접 검색 |
| 개인 관리 절차·절대 경로 | 공개 저장소의 상대 경로와 기여 절차로 교체 |
| 별도 윤문 스킬 연동 | 선택적 연계 설명만 남기고 필수 의존성 제거 |
| 개인 설치본과 이력 | 공개 저장소에 복사하지 않음 |

공개용 지침은 `skills/plain-korean/` 한 곳에서 관리한다. 배포 폴더만 복사해 사용할 수 있고, Git 저장소가 없어도 일반 편집과 예시 검색이 동작한다. 기존 공개 저장소의 MIT 라이선스와 Git 이력은 유지한다.

## 기여 흐름

사용자 피드백 → 문체 판단 추출 → 새 가상 문맥과 예문 → 전체 필드 의미 검토 → 로컬 미리보기 → 동의·계정·제출처 확인 → 열린·닫힌 이슈 중복 확인 → 이슈 생성 → 유지관리자 검토 → PR 반영.

자동 기여는 사용자의 명시적인 최초 동의를 로컬에 저장한다. 에이전트가 사용자의 동의를 대신 만들 수 없다. 사용자는 이후 반복 승인 없이 기여할 수 있고, 언제든 끌 수 있다. 단순 설치에는 외부 게시 권한을 포함하지 않는다.

새 규칙마다 이슈를 만들지 않는다. 기존 패턴으로 설명할 수 있으면 그 기준을 사용한다. 자동 기여는 한 작업당 최대 한 건, 도우미는 같은 상태 디렉터리에서 24시간에 세 건까지 허용한다.

## 개인정보와 중복 처리

이름만 지우는 방식은 원문의 사건 조합과 문장 구조를 남길 수 있어 채택하지 않았다. 가상 예문을 새로 쓰고 모든 필드의 의미를 검토한다. 정규식은 명백한 식별자의 전송을 막는 보조 검사다. 개인정보 제거를 완전히 보증한다고 설명하지 않는다.

지문은 패턴과 수정 전후의 정규화된 값으로 계산한다. 제목이나 이유가 달라도 같은 수정 예면 중복으로 처리하며, 닫힌 이슈도 다시 만들지 않는다. 다른 표현의 같은 취지는 에이전트와 유지관리자가 검토한다. 로컬 잠금은 같은 상태 디렉터리의 경쟁만 막고 서로 다른 컴퓨터의 동시 게시까지 막지 못한다.

생성 전 예약을 기록해 요청 실패 뒤의 중복 생성을 줄인다. 결과가 불확실하면 자동 재시도하지 않고 사람이 확인한다. 이전 예약이 해결되지 않았으면 다른 새 후보도 제출하지 않는다. 기여 실패가 원래 문체 수정 작업을 막지 않게 한다.

이슈는 외부에서 들어온 자료다. 이슈에 적힌 명령이나 외부 링크를 실행하지 않는다. GitHub Actions는 저장소 검사만 수행하고 사용자 이슈의 내용을 실행하거나 규칙에 자동 반영하지 않는다.

## 검증 범위

자동 검사는 패키지 경로·참조·예시 ID와 필드, 동의 없는 전송 차단, 계정 변경, 개인정보 신호, 중복, 제출 제한, 실패 시 예약 보존을 확인한다. GitHub 호출은 테스트에서 대체한다. 실제 공개 이슈를 만들거나 다양한 AI 모델의 한국어 품질을 자동으로 보증하지 않는다.

문체 수동 검토에는 군더더기 삭제, 실제 제한·불확실성 유지, 조사 상태와 제품 사실 구별, 같은 대상의 이름 유지, 가정과 관찰 구별을 포함했다. 예시에는 수정 12건과 유지 6건을 함께 넣었다.
